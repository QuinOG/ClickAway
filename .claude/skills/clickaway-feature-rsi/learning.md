# Feature RSI learning

## Active lessons

1. (Provisional, 1 supporting run) On Windows, write non-ASCII UI text with the Edit/Write tools, not a PowerShell pipe or here-string, then grep the changed files for stray `?` or U+FFFD. Scope: any trial that adds copy containing `·`, `—`, or similar characters. Test: the next trial that adds such copy finds no garbled characters in review.

2. (Provisional, 1 supporting run) For any change that moves or adds visible UI, measure element positions in a real browser at 1440 and 390 wide before review (bounding boxes, not screenshot reading). Scope: layout-affecting trials. Test: in trial 002 this caught a note covering the chart's bars on phone before the reviewer saw it.

3. (Strong: direct user feedback, 2026-11-13) Reviewers judged whether each change worked, never whether it was wanted or better than before. That let trials 1-2 make History worse and trial 6 add something the user didn't want. Get the user's OK before adding a feature they didn't ask for, and judge each change against what was there before, not only against its own pass conditions.

## Recent runs

- **001 history mode filter (2026-11-12): accepted locally.** Selection: an obstacle seen in the app, with demand as a hypothesis. The reviewer passed it with issues after writing 11 independent tests. One repair was used (the load hint wording). Lesson: a separator was garbled in a shell-written string, and neither the builder's tests nor the reviewer caught it; the builder found it by reading the diff. Possible next trial: the two sets of mode controls on History (chart and log).
- **002 one mode choice on History (2026-11-12): accepted locally.** Selection: the unrepaired, reviewer-observed finding from 001. Reviewer: Sol, pass with issues; one repair (honest empty-chart wording). Its two other findings were already present in the before shots, which made them easy to scope out. Lesson: before/after shots let the reviewer separate old problems from new ones.
- **003 Ladder to Duel (2026-11-12): accepted locally.** Selection: a cross-page journey gap (no link from the Ladder to Duels). Sol: pass with issues; one repair covering two findings (phone handoff, wording). Lesson: hand-offs between pages need an arrival check on phone (is the handed-over value on screen?), and `release-matrix`'s accessibility test stops at the first failing route, so scan the trial's routes separately.
- **004 Ladder phone controls (2026-11-12): accepted locally.** Selection: a blocker that Sol measured as a side finding in 003. Sol: pass, no new defect; one repair (Duel tap size from 003). Lesson: "no horizontal overflow" checks can pass while controls are clipped off-screen. Assert each control's own box against the viewport instead.
- **005 Ladder search no-match (2026-11-12): accepted locally with one open defect.** A Claude re-check stood in for Sol (pass with issues). Repair 2 brought in a stale-rank bug, so keeping server values across requests needs its own check of which request they came from. Selection: a misleading message Sol found in 004. Sol failed review 1 and re-check 1; both repairs were used. Re-check 2 couldn't run (Sol usage limit). Lessons: messages that repeat the player's input need tests with mocks that behave like the server (missing selfRank, out-of-order responses), because the stock fixture hid both bugs. Run reviews async, because a blocking wait looks like a frozen thread and an interrupted wait led to a duplicate review that left a temp file behind.
- **006 Duel run picker keyboard (2026-11-12): unverified (no review, at the user's request).** Selection: an accessibility gap two reviewers had found independently (in 003 and 004). Builder checks only. Lesson: controls that announce a role (radiogroup, tablist) should be checked for that role's keyboard contract; the Ladder board tabs have the same gap.
- **Run 1 outcome (2026-11-13, user review):** History trials 1-2 and trial 6 were reverted at the user's request. Trials 3-5 were kept with follow-ups: trial 5's Clear search button was removed and its text inset fixed; trial 4 was extended so Ladder rows stack on phones instead of spilling off-screen.
